## 1. Что это

TON Nexus — Telegram Mini App: биржа заданий (амбассадоры и админы создают задания с бюджетом в TON, пользователи выполняют и получают TON), «майнер» (реактор с усилениями), ежедневная отметка, колесо призов, мини-игра «Башня» с месячным топом и призами, рейтинги. Вывод TON — вручную через очередь заявок.

Владелец продукта — Сергей. Он не программист, сидит на Windows, на сервере новичок.

## 2. Стек и структура репозитория

| Часть | Стек | Где |
|---|---|---|
| API | Python, FastAPI, SQLAlchemy 2 (async), Alembic, PostgreSQL (asyncpg) | `backend/` |
| Mini App | React 19, Vite 6, TypeScript 5.7, Tailwind 4, Framer Motion, TanStack Query 5, zustand, react-router 7 | `frontend/` |
| Бот | aiogram, только `/start`, `/help`, `/ping` | `bot/main.py` |
| Деплой | systemd-раннер, без Docker | `scripts/deploy-runner.sh`, `deploy/systemd/` |
| Документы | дизайн, схема, деплой | `docs/` |

Бэкенд (`backend/app/`):

- `main.py` — приложение FastAPI; при старте `seed_economy` дописывает недостающие настройки экономики.
- `api/` — роутеры, все под префиксом `/api/v1` (`api/__init__.py`): `me`, `miner`, `tasks`, `admin`, `deploy`, `economy`, `withdraw`, `engagement`, `tower`, `ratings`. Текущий пользователь — `api/deps.py: get_current_user` (заголовок `X-Telegram-Init-Data`; забаненным — 403).
- `services/` — вся логика. Ключевые: `balance.py` (деньги), `tasks.py` (задания и проверка заявок), `roles.py` (права), `economy.py` / `economy_seed.py` / `economy_admin.py` (настройки), `levels.py` (`add_xp` + журнал `xp_events`), `gameday.py` (сутки и месяцы по МСК), `tower*.py`, `ratings.py`, `withdraw.py`, `miner.py`, `upgrade*.py`.
- `models/` — модели SQLAlchemy; все экспортируются из `models/__init__.py` (новую модель добавляй и туда — тесты создают схему через `Base.metadata.create_all`).
- `core/config.py` — настройки из окружения (`TELEGRAM_OWNER_IDS`, `TELEGRAM_DEPLOYER_IDS` и др.).
- `alembic/versions/` — миграции `001`…`006`. **Следующая — `007`**, `down_revision = "006"`. Образец стиля — `006_ratings_xp_events.py`.
- `tests/` — `unittest`, SQLite в памяти (`aiosqlite`), образец — `tests/test_ratings.py` (`run_db`, `make_user`).

Фронтенд (`frontend/src/`):

- `pages/` — экраны (`Home`, `Tasks`, `TaskDetail`, `TaskCreate`, `Inbox`, `Wallet`, `WithdrawQueue`, `Miner`, `Wheel`, `Tower`, `TowerTop`, `Ratings`, `Owner`, `Deploy`, `Kit`).
- `components/ui/` — набор компонентов дизайн-системы (`Panel`, `Button`, `HoldButton`, `Sheet`, `Tabs`, `List`, `Num`, `States` …); `components/owner/` — кабинет владельца (`OwnerShell`, `SettingsList`).
- `api/` — `client.ts`, `hooks.ts` (TanStack Query), `types.ts`.
- `lib/routes.tsx` — маршруты; `lib/settingsMeta.ts` — русские подписи и поля настроек экономики.
- `styles/` — CSS; `styles/animBudget.test.ts` проверяет бюджет анимаций.

Кабинет владельца: `pages/Owner.tsx`, вкладки «Обзор», «Промо», «Экономика». Настройки экономики группируются по `SETTING_CATALOG` (`services/economy_admin.py`) и `GROUP_RU`/`GROUP_ORDER` (`components/owner/SettingsList.tsx`).

## 3. Как запускать тесты

Бэкенд (из `backend/`):

```
pip install -r requirements.txt aiosqlite
python -m unittest discover -s tests
```

Фронтенд (из `frontend/`):

```
npm ci
npx vitest run
npx tsc -b
npm run build
```

Все четыре команды фронтенда и тесты бэкенда должны проходить перед PR. В описании PR укажи, что запускал и что вышло.

## 4. Инварианты кода (нарушать нельзя)

1. **Деньги двигаются только через `services/balance.py`: `credit()` / `debit()`.** Они блокируют строку пользователя (`get_user_for_update`, `FOR UPDATE`) и пишут запись в `balance_history` с `balance_type`, `reference_type`, `reference_id` и `balance_after`. Никаких `user.balance += …` в обход. Действующие `balance_type`: `daily`, `miner`, `prize_wheel`, `promo`, `tasks`, `tower_prize`, `upgrade_burn`, `withdraw`. Новый тип — только осознанно и с тестом.
2. **Суммы — `Decimal`, баланс — `Numeric(18,8)`.** Округление денег — вниз (`ROUND_DOWN`, см. `services/tower_prizes.py`) или квантование до 8 знаков (`_q` в `services/tasks.py`). Никаких `float` в денежных расчётах.
3. **Идемпотентность.** Повторный запрос не должен платить второй раз: уникальные ключи (`UniqueConstraint`, см. `models/tower.py`), проверка статуса под блокировкой (`_lock_task` + `refresh` в `review_submission`). Тесты на двойные выплаты — `tests/test_double_payouts.py`.
4. **Границы суток и месяцев — по Москве (МСК, UTC+3)**: `services/gameday.py` (`MSK`, `game_day`, `day_start`). В БД время хранится в UTC (`DateTime(timezone=True)`).
5. **Роли:** владелец > админ > амбассадор > пользователь (`services/roles.py`). Владелец — Telegram ID из `TELEGRAM_OWNER_IDS` (окружение сервера), админ — `users.is_admin`, амбассадор — `users.is_ambassador`. `is_deployer` — отдельное техническое право (только деплой). Есть `users.is_banned`.
6. **Настройки экономики** — таблица `economy_settings` (JSON). Значения по умолчанию — `DEFAULTS` в `services/economy_seed.py`; чтение — `services/economy.get_setting`; запись — только владелец (`api/economy.py`, `_require_owner`) через `services/economy_admin.set_setting` (там же валидация/нормализация по ключу). Новая настройка = запись в `DEFAULTS` + строка в `SETTING_CATALOG` + метаданные в `frontend/src/lib/settingsMeta.ts`.
7. **Миграции:** следующая — `007`. Уже слитые миграции (`001`–`006`) **не редактировать никогда**, только новые.
8. **Деплой** — кнопка «Обновить тест» в приложении (экран «Деплой», `components/DeployPanel.tsx`, `docs/DEPLOY_TELEGRAM.md`). Раннер `scripts/deploy-runner.sh`: git → pip (если изменились зависимости) → `alembic upgrade head` → сборка фронта → перезапуск API → проверка здоровья. **Бот при этом не перезапускается.** Миграция обязана проходить на рабочей базе с данными.
9. **Планировщика нет** (ни cron, ни очередей). Всё, что «по времени», считается лениво при запросе или запускается владельцем кнопкой (как закрытие месяца «Башни»). Не добавляй фоновые процессы без отдельной задачи.
10. `users.referred_by_id` существует, но **нигде не заполняется**; настройка `referral_reward` не используется. Рефералы — отдельная будущая задача.

## 5. Правила Сергея

- **Маленькие PR, одна задача — один PR.** Не смешивай задачи, не делай «заодно».
- **Никогда не мержи.** PR сливает только Сергей после ревью.
- **Описание PR — коротко и по-русски**: что сделано, как проверить, что не вошло, чек-лист из `docs/tasks/README.md`.
- **Скриншоты** для любого видимого изменения UI (ширина 360 и 390 px, тема «Ночь»; если касается светлой — и «Дневной HUD»).
- **Без Docker.**
- **Команды для сервера** (если вдруг нужны) — по одной, пошагово, с пояснением. Файлы — только через `printf`, **никаких `nano` и heredoc** (Сергей на Windows и новичок). Сам на сервере ничего не выполняй.

## 6. Дизайн-система «Ночной контур» (Luxury Metal)

Полное описание — `docs/DESIGN.md`. Перед любым UI прочитай минимум: §3.7 «Производительность материала», §5 «Отступы, сетка, ритм, касания», §7 «Компоненты», §11 «Отклик», §12 «Движение» (и §12.1 — бюджет анимаций), §14 «UX-правила», §15 «Делать / не делать», §16 «Чек-лист нового экрана». Используй компоненты из `frontend/src/components/ui/`, не изобретай свои.

Жёсткие правила:

- **Никакого `backdrop-filter`** и `filter: blur()` в реальном времени.
- **Никаких бесконечных анимаций свечения** (`filter`, `box-shadow`, `text-shadow` не анимируются). Движение — только `transform` и `opacity`.
- **Не больше 19 бесконечных анимаций на экран, включая стоящие на паузе** (пауза не убирает анимацию из `document.getAnimations()`). Новый экран без нужды — 0 бесконечных анимаций.
- **Статичная версия** для слабых устройств (`html.low-end`) и для «уменьшить движение» (`prefers-reduced-motion`).
- Цвета — только токены из DESIGN.md §2; нет hex в `.tsx`.

Чек-лист полировки (проверь на 360 и 390 px):

- [ ] всё отцентровано, ничего не съехало;
- [ ] отступы из ряда 4 · 8 · 12 · 16 · 24 · 32, поля экрана 16;
- [ ] ничего не обрезается (длинные имена, большие числа, перенос строк);
- [ ] контент не уходит под нижний док и главную кнопку;
- [ ] все касаемые элементы ≥ 44×44 px;
- [ ] есть состояния «загрузка», «пусто», «ошибка» (с «Повторить»);
- [ ] денежное действие — сводка и удержание (`HoldButton`).

## 7. Правила платежей Telegram (обязательно)

Модель, утверждённая Сергеем:

- **TON** — бюджеты заданий, пополнение баланса, вывод заработанного.
- **Telegram Stars** — цифровые товары (бустеры, усиления майнера). TON для них — только вторым способом и **по той же цене**.
- **Рефералы — один уровень**, награда только за активность приглашённого (условие `friend_rule`), не за сам факт приглашения.

Запрещено:

- продавать цифровые товары/услуги внутри Mini App иначе, чем через Stars (Bot Developer Terms, п. 6.2);
- конвертировать Stars в выводимый TON (никакого «Stars → TON» ни прямо, ни через внутренний баланс);
- многоуровневые реферальные схемы, MLM, «банк»/пирамиды (п. 5.2(d));
- для крипты — только TON и только через TON Connect.

## 9. Никогда

- Никаких секретов в коде, документах, коммитах и PR: токенов, ключей, паролей, IP-адресов, Telegram ID, строк подключения к БД. Конфиг — только через переменные окружения и `.env.example` с пустыми значениями.
- Никакого `git push --force`, переписывания истории, удаления веток.
- Не мержить PR. Не коммитить в `main` напрямую.
- Не редактировать слитые миграции (`001`–`006`).
- Не трогать денежные пути (`balance.py`, выплаты, вывод, бюджеты заданий, призы) без тестов на них.
- Не добавлять Docker, планировщики и фоновые процессы без отдельной задачи.
- Не выполнять ничего на сервере и не просить доступ к нему.
- Не выходить за рамки своей задачи: всё «заодно» — отдельным предложением в описании PR.
